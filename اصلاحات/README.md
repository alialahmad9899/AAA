# إصلاحات التسجيل — API فقط

هذه الحزمة تحتوي على ملفات من طبقة Laravel API حصراً. لا تستبدل أي ملف داخل
\`app/Http/Controllers/\` خارج مجلد \`Api\`، ولا تستبدل ملفات الموقع أو واجهاته.

## الملفات ومسارات الاستبدال

انسخ محتوى كل ملف إلى المسار نفسه داخل \`public_html\`:

| الملف داخل هذا المجلد | المسار المستهدف |
|---|---|
| \`app/Http/Controllers/Api/AuthController.php\` | \`public_html/app/Http/Controllers/Api/AuthController.php\` |
| \`app/Http/Controllers/Api/ProfileController.php\` | \`public_html/app/Http/Controllers/Api/ProfileController.php\` |
| \`app/Http/Requests/AuthRequest.php\` | \`public_html/app/Http/Requests/AuthRequest.php\` |
| \`app/Http/Requests/ProfileRequest.php\` | \`public_html/app/Http/Requests/ProfileRequest.php\` |
| \`app/Http/Middleware/EmailVerifiedApi.php\` | \`public_html/app/Http/Middleware/EmailVerifiedApi.php\` |

## ما تم إصلاحه

- إنشاء المستخدم والعضوية والصورة ضمن معاملة واحدة، مع إيقاف التسجيل برسالة مناسبة إذا لم تكن باقة التسجيل الأساسية موجودة.
- دعم صورة اختيارية في \`/api/signup\` والتحقق من نوعها وحجمها وربط ملفها وسجل Upload بحساب المستخدم.
- إذا فشل إنشاء الحساب أو العضوية أو سجل الصورة، تُلغى معاملة قاعدة البيانات ويُحذف ملف الصورة المرفوع ضمنها.
- قبول طلب تحديث المعلومات الأساسية من دون هاتف جديد، مع الحفاظ على الهاتف المخزن وعدم استبداله بقيمة فارغة.
- حفظ صورة الملف الشخصي وربط \`photo\` و\`avatar_original\` و\`avatar\` ضمن معاملة واحدة.
- السماح بطلبات الكتابة الخاصة باستكمال الملف الشخصي فقط (المعلومات الأساسية، المواصفات الجسدية، التعليم، العمل، الإقامة، الخلفية الدينية، وتوقعات الشريك) قبل تأكيد البريد. لا يشمل الاستثناء طلبات القراءة أو المحادثات أو الإشعارات أو بقية API.
- إعادة HTTP 403 لطلبات API التي يمنعها عدم التحقق من البريد.

## حدود الإصلاح بسبب شرط API فقط

شاشة Flutter الحالية تستدعي \`signup()\` من دون تمرير \`photoFile\`، ثم ترفع الصورة في طلب منفصل. الإصلاح أعلاه يجعل طلب الرفع المنفصل صالحاً من جهة API، كما يدعم إرسال الصورة مع طلب إنشاء الحساب في حال أرسلها العميل.

لكن لا يمكن من PHP وحده جعل شاشة Flutter تنتظر نجاح كل مرحلة؛ فالتطبيق يتجاهل حقول \`success\` التي تعيدها بعض دوال الحفظ، وينتقل للخطوة التالية بعد اكتمال الطلبات. كذلك فإن حفظ الحدين الأدنى والأعلى لنطاقات الطول والوزن يتطلب تغييراً في منطق التطبيق أو مخطط البيانات، وليس مجرد تعديل API الحالي. لم نغيّر ملفات Flutter احتراماً لشرط أن تكون التعديلات على API فقط.

## قبل اعتمادها على الاستضافة

1. احتفظ بنسخة احتياطية من الملفات الخمسة الأصلية.
2. استبدل الملفات في المسارات الموضحة أعلاه فقط.
3. تأكد من أن قرص Laravel المسمى \`public\` مربوط بمجلد التخزين العام.
4. اختبر التسجيل بحساب تجريبي: إنشاء الحساب، رفع الصورة، ثم فتح الملف الشخصي والتحقق من ظهور الصورة.
5. اختبر حساباً لم يتم التحقق من بريده؛ يجب أن يسمح له بحفظ خطوات إكمال الملف الشخصي، بينما تبقى طلبات القراءة والمحادثات والإشعارات وبقية مسارات API خاضعة للتحقق.

لم يتم تنفيذ اختبار فعلي على قاعدة بيانات الإنتاج أو خادم الاستضافة من هذه الحزمة.
