# تعليمات العمل الثابتة

هذه التعليمات إلزامية عند العمل على هذا الجزء من مشروع وصال.

## نطاق العمل المعتمد — أولوية قصوى
**الهدف هو تطبيق وصال للموبايل ولوحة تحكم الأدمن فقط. الموقع العام وواجهات الأعضاء في الويب خارج نطاق العمل.**

- نفّذ التعديلات التي تخدم تطبيق Flutter للموبايل: API، منطق Backend، التحقق من البيانات، الصلاحيات، التخزين، الإشعارات، الاشتراكات، والربط مع قاعدة البيانات بحسب الحاجة المثبتة.
- يُسمح بتعديل Laravel API والملفات الخلفية المشتركة التي يعتمد عليها التطبيق، بعد تتبع الاستدعاء من التطبيق إلى المسار والـController والـModel وقاعدة البيانات.
- يُسمح بتعديل **لوحة تحكم الأدمن فقط** عندما يطلب المستخدم ذلك، أو عندما تكون هناك حاجة تشغيلية واضحة ومثبتة لإدارة ميزة تخص التطبيق.
- لا تعدّل الموقع العام أو واجهات الأعضاء: لا صفحات الزوار أو الأعضاء، ولا واجهات Blade الخاصة بالموقع، ولا CSS/JS أو الأصول أو التصميم أو SEO أو التوافق مع الشاشات الخاصة به.
- لا تنفّذ تحسينات أو إصلاحات للموقع لمجرد أن ملفات الموقع موجودة في المستودع. وجود الملف لا يجعله ضمن النطاق.
- لا تغيّر Web Routes أو Web Controllers أو واجهات الموقع العامة عند معالجة مشكلة في الموبايل. ابحث أولاً عن مسار API الذي يستدعيه التطبيق.
- عند وجود ملف Laravel مشترك بين API ولوحة الأدمن أو بين أكثر من قناة، افحص الاستخدامات والأثر الجانبي ولا تغيّر سلوكاً خارج النطاق دون ضرورة موثقة.
- الموقع الحالي مخطّط لإيقافه تدريجياً مستقبلاً والإبقاء على تطبيق الموبايل ولوحة الأدمن. لا تنشئ ميزات جديدة مرتبطة بالموقع العام، لكن لا تحذف أو توقف الموقع أو قواعده أو ملفاته الآن دون طلب صريح.
- إذا كان الطلب غامضاً بين التطبيق ولوحة الأدمن والموقع، اعتمد التطبيق كوجهة افتراضية، واسأل فقط إذا تعذّر حسم النطاق من السياق.

## المصدر المعتمد
- اعتمد أحدث الملفات التي رفعها المستخدم إلى هذا المجلد باعتبارها المصدر الأساسي.
- قبل أي تعديل، افحص النسخة الحالية وسجل التعديلات، ولا تستخدم نسخاً قديمة أو تسترجع ملفات سابقة من الذاكرة أو من أرشيف قديم.
- طبّق كل تعديل جديد فوق آخر حالة صحيحة من الملفات نفسها، وحافظ على الإصلاحات السابقة.

## طريقة التنفيذ
- افهم بنية المشروع والاعتماديات والمسارات والارتباطات قبل التعديل.
- عدّل الملفات الأصلية في مكانها داخل المشروع، وحافظ على أسمائها ومساراتها وبنية المجلدات.
- لا تنفّذ إعادة كتابة واسعة أو تحذف ميزة خارج نطاق الطلب.
- افحص أثر التعديل على الملفات المرتبطة، ولا تغيّر API أو قاعدة البيانات أو واجهات أخرى إلا عند الحاجة المثبتة لخدمة التطبيق أو لوحة الأدمن.
- في مشكلات الموبايل، تتبّع المسار كاملاً: شاشة Flutter ← ApiService ← API Route ← API Controller/Request/Resource ← Model/Database، ثم اختبر الاستجابة والحفظ والقراءة والصلاحيات.
- لا تعتبر تعديل واجهة الموقع حلاً لمشكلة في التطبيق. لا تلمس Views إلا إذا ثبت أنها جزء من لوحة تحكم الأدمن المطلوبة.
- نفّذ الاختبارات والتحققات المناسبة، وميّز بوضوح بين الاختبار المنفذ فعلياً وما لم يمكن اختباره.

## التسليم بعد كل دفعة
- أنشئ ZIP يحتوي فقط على الملفات التي عُدّلت أو أُنشئت في هذه الدفعة، مع الحفاظ على المسارات النسبية الأصلية داخل هذا الجزء من المشروع.
- لا تضع المشروع كاملاً داخل حزمة الإصلاحات.
- تحقق من سلامة ZIP ومن وجود كل الملفات المطلوبة قبل إرسال الرابط.
- حدّث سجل PROJECT_NOTES.md في جذر المستودع بعد كل دفعة، ولا تحذف الملاحظات أو الاستنتاجات السابقة.
- اذكر الملفات المتغيرة، سبب المشكلة، الإصلاح، نتائج الاختبارات، وما بقي من مهام.
- وضّح في كل دفعة هل الملفات تتعلق بتطبيق الموبايل أو API أو لوحة الأدمن؛ ولا تُدرج ملفات الموقع العام ضمن الإصلاحات.

## GitHub والاستضافة
- لا تدّعِ أن التعديلات حُفظت على GitHub أو دُمجت في main أو نُشرت على الاستضافة إلا بعد تنفيذ العملية والتحقق منها.
- لا تنشر على الاستضافة ولا تغيّر main أو تحذف ملفات أو فروع دون طلب صريح.
- عند استخدام فرع مستقل، اذكر اسمه وحالة الدمج بوضوح.

## الاستمرارية
- اقرأ هذه التعليمات وPROJECT_NOTES.md قبل كل دفعة جديدة.
- عند تعارض المعلومات، اعتمد الملفات الأحدث التي رفعها المستخدم بعد التحقق من تواريخها ومحتواها، وسجّل سبب اختيار النسخة.
- لا تطلب من المستخدم إعادة معلومات أو ملفات موجودة بالفعل في النسخة الحالية.


## نطاق مجلد «المشروع»
يحتوي هذا المجلد على Backend Laravel والـAPI ولوحة تحكم الأدمن. قد تبقى داخله ملفات الموقع العام القديمة لأسباب التوافق أو لأنها ستُستخدم كمرجع تاريخي فقط؛ وجودها لا يعني أنها ضمن نطاق التطوير.

- **API للموبايل:** المسارات والـControllers والـRequests والـResources والـModels والخدمات وقواعد البيانات التي يعتمد عليها تطبيق Flutter.
- **لوحة الأدمن:** المسارات والـControllers والـViews والـAssets الخاصة بإدارة التطبيق فقط، عند الطلب أو الحاجة المثبتة.
- **خارج النطاق:** صفحات الموقع العام وواجهات الأعضاء والزوار، وملفات Blade/CSS/JS والتصميم الخاصة بها، وأي تحسين أو صيانة للموقع الذي سيُلغى مستقبلاً.
- افصل بدقة بين ملفات API وملفات لوحة الأدمن وملفات الموقع العام قبل أي تعديل؛ لا تعتمد على اسم المجلد وحده.
- حافظ على التحقق والحماية والصلاحيات وCSRF حيث تنطبق على لوحة الأدمن، وعلى المصادقة والتفويض والتحقق من المدخلات في API.
- لا ترفع ملفات .env أو كلمات المرور أو مفاتيح API أو بيانات الأعضاء أو نسخ قواعد البيانات إلى GitHub أو حزم التسليم.
